# Support docs: local stack + sample patients

Community questions keep landing on the same gap: people get a local Medplum running, then cannot sign in, cannot find patients, or cannot query data they just uploaded. First-boot seed creates a Super Admin user only. It does not create a regular project or any `Patient` resources. The hosted import tutorial points at `app.medplum.com`, so a local setup looks empty.

## Clustered questions

1. [Discussion #2957 — Setting up self-hosted environment for client testing](https://github.com/medplum/medplum/discussions/2957)
   How do I authenticate against a local/docker Medplum API, create a project, and get a FHIR access token? Seed credentials alone do not expose a ready FHIR app project.
2. [Issue #6218 — Super Admin cannot be logged in](https://github.com/medplum/medplum/issues/6218)
   Fresh clone + Docker Postgres/Redis, `admin@example.com` / `medplum_admin` rejected. A later comment asked the docs to state those credentials explicitly.
3. [Issue #7773 — `Invalid client` with default Client Application credentials on local docker-compose](https://github.com/medplum/medplum/issues/7773)
   User uploaded patients to a local stack, then the TypeScript SDK failed because `baseUrl` still pointed at the hosted API instead of `http://localhost:8103`.

Related search demand: [Issue #10082](https://github.com/medplum/medplum/issues/10082) recorded the Algolia query “how to seed patients in test app”.

### Discussion #2957

A local or docker Medplum API is usable after first-boot seed, but seed only creates a Super Admin user (`admin@example.com` / `medplum_admin`) and the Super Admin project — not a regular app project and not any FHIR patients.

Short path:

1. Wait until `http://localhost:8103/healthcheck` returns `"ok": true`.
2. Open `http://localhost:3000/register` and create a regular project (or sign in as Super Admin and then register one).
3. In that project, create a Client Application (Project → Clients).
4. Call the SDK or CLI with `baseUrl: 'http://localhost:8103/'` and those client credentials.

Step-by-step, including a synthetic patient bundle: https://www.medplum.com/docs/contributing/local-sample-patients

### Issue #6218

Those are the intended first-boot Super Admin credentials: `admin@example.com` / `medplum_admin`. They are created only after the server finishes its first migrate+seed. If that process is interrupted, login fails until you drop the `medplum` database or the Postgres Docker volume and start the server once, cleanly.

The credentials, ports, and “no patients yet” note are now in https://www.medplum.com/docs/contributing/local-sample-patients and https://www.medplum.com/docs/contributing/run-the-stack

### Issue #7773

`Invalid client` here usually means the SDK is talking to the hosted API (`https://api.medplum.com`) while the Client Application exists only on localhost. Set `baseUrl: 'http://localhost:8103/'` (and use the client id/secret from the **same** local project that holds the uploaded patients).

```ts
const medplum = new MedplumClient({
  baseUrl: 'http://localhost:8103/',
  clientId: process.env.MEDPLUM_CLIENT_ID,
  clientSecret: process.env.MEDPLUM_CLIENT_SECRET,
});
```

Full local import + query walkthrough: https://www.medplum.com/docs/contributing/local-sample-patients

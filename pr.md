# Support cluster: local Medplum + synthetic test patients

Community questions about standing up a local Medplum stack, signing in, and loading test patients keep landing in GitHub issues and discussions. The existing pages split the answer across contributing, self-hosting, and hosted-only tutorials, and several commands/versions were stale.

This PR adds one how-to and corrects the pages people already find.

## Clustered questions

1. [Discussion #2957 — Setting up self-hosted environment for client testing](https://github.com/medplum/medplum/discussions/2957)
   How do I authenticate against a local Docker Medplum, use the default admin, create a project/client, and reach the FHIR API?

2. [Issue #6218 — Super Admin cannot be logged in](https://github.com/medplum/medplum/issues/6218)
   Fresh local clone + Docker Postgres/Redis: `admin@example.com` / `medplum_admin` does not work. A comment asked to put those credentials in the docs (they were only on Run the Stack, not on the Docker Compose page).

3. [Issue #7773 — `Invalid client` with default Client Application credentials on the full local Docker stack](https://github.com/medplum/medplum/issues/7773)
   After launching `docker-compose.full-stack.yml` and uploading patients, the TypeScript SDK returns `Invalid client` when using the local client ID/secret.

### Discussion #2957

The shortest path is the full-stack compose file: it starts Postgres, Redis, the API on `http://localhost:8103`, and the app on `http://localhost:3000`. Wait until `GET /healthcheck` returns `ok`, then sign in as `admin@example.com` / `medplum_admin`. That user is Super Admin only — create a regular project (`/signin?project=new`), then a Client Application under Project → Clients. Point your library at `baseUrl: 'http://localhost:8103/'` and use those local credentials. The step-by-step, including a synthetic patient bundle, is here: https://www.medplum.com/docs/contributing/local-dev-sample-data

### Issue #6218

Those credentials are the seed fallbacks in `packages/server/src/seed.ts` (`admin@example.com` / `medplum_admin`) when `defaultSuperAdminEmail` and `defaultSuperAdminPassword` are unset. They only exist after the first seed finishes — check `http://localhost:8103/healthcheck` first. If seed was interrupted, reset the Docker volume. The values are now on the Docker Compose page and in https://www.medplum.com/docs/contributing/local-dev-sample-data (they were previously only on Run the Stack).

### Issue #7773

A client created on localhost is only valid against that server. Set `baseUrl: 'http://localhost:8103/'` on `MedplumClient` (not `https://api.medplum.com`) and call `startClientLogin` with the ID/secret from **that** project's Clients page. The seed does not create a default client unless you set `defaultSuperAdminClientId` / `defaultSuperAdminClientSecret` before first start. Full walkthrough: https://www.medplum.com/docs/contributing/local-dev-sample-data
